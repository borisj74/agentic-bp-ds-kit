# Agentic BP DS — the rules, written out

Reverse-engineered from the repo at commit `fea69d8` (branch `main`, 398 commits). Every rule is tagged:

- **[code]** — confirmed in code: a generator, a test, a review rule, or the same shape in every file of a group.
- **[guess]** — my reading. Plausible, not enforced anywhere I could find.

Line references are `path:line` where a single line carries the rule.

---

## 1. Token tiers

### 1.1 Four tiers, one direction **[code]**

```
source/*.txt  →  primitives.css (--ref-*, --ui-*, scale)  →  semantic.css (--bg-*, --text-*, …)  →  component CSS module
```

- `src/tokens/source/*.txt` is the hand-edited source. It mirrors the Figma variable collections (`scripts/build-tokens.mjs:2`).
- `npm run tokens` (`scripts/build-tokens.mjs`) writes `src/tokens/primitives.css` and `src/tokens/semantic.css`. Both files start with `/* GENERATED by scripts/build-tokens.mjs`. Never hand-edit them.
- `src/tokens/typography.css` and `src/tokens/layout.css` are **not** generated. They are hand-written and carry the text roles and the layout classes.
- Colour in a component comes from a semantic role in `semantic.css` only. Non-colour roles (`--space-*`, `--control-*`, `--radius-*`, `--border-width-*`, `--icon-size-*`, `--opacity-*`, `--motion-*`, `--focus-offset`, `--target-min`, `--layout-*`) are declared in the generated `primitives.css` and components read them directly — they are roles, not ramps. **[code]**
- What is banned outside `src/tokens` is the ramp itself: a `--ref-*` or `--ui-*` var is a review error `bp/primitive-token` (`scripts/review/rules.mjs:84-90`). So is a var no token file defines.

### 1.2 Source file formats **[code]**

| File | Row format | Becomes |
| --- | --- | --- |
| `ref.txt` | `name\|Cobalt\|Sunset\|Olive\|BP-Legacy` | `:root` + `[data-brand="sunset\|olive\|bp-legacy"]` |
| `ui.txt` | `name\|Light\|Dark` (values alias `ref/*`) | `:root, [data-theme="light"]` + `[data-theme="dark"]` |
| `semantic.txt` | `name\|Light\|Dark` (values alias `ui/*`) | same two blocks, in `semantic.css` |
| `scale.txt` | `name\|default` or `name\|default\|compact\|comfortable` | `:root, [data-density]` + `[data-density="compact\|comfortable"]` |
| `effects.txt`, `motion.txt`, `opacity.txt`, `layout.txt` | `name\|value` | `:root, [data-density]` |

- `#` starts a comment line; blank lines are dropped (`build-tokens.mjs:12-16`).
- `{a/b}` is an alias and becomes `var(--a-b)` (`build-tokens.mjs:19`).

### 1.3 Name → CSS var **[code]**

`build-tokens.mjs:18`: `--` + name with `/` → `-`, and a leading `background-` → `bg-`.

- `background/brand/hover` → `--bg-brand-hover`
- `text/neutral/strong` → `--text-neutral-strong`
- `ref/space/400` → `--ref-space-400`

### 1.4 Units **[code]**

`build-tokens.mjs:41`: a scale value gets `px` appended **unless** it is an alias (`{…}`) or its name starts with `font-weight`, `line-height` or `letter-spacing` (also under a `ref/` prefix). So line heights are unitless ratios and letter spacings carry their own `em`.

### 1.5 Switch selectors **[code]**

- Theme: `[data-theme="light"]` (same as `:root`) and `[data-theme="dark"]`.
- Brand: `:root` is Cobalt; `[data-brand="sunset"]`, `[data-brand="olive"]`, `[data-brand="bp-legacy"]`.
- Density: `:root` is Default; `[data-density="compact"]`, `[data-density="comfortable"]`. Alias-holding blocks are re-declared on `[data-density]` so an alias resolves against the nearest density (`build-tokens.mjs:44-46`).

## 2. Scales and their base values (Default density)

### 2.1 Space **[code]** (`src/tokens/source/scale.txt`)

| Role | px | ref |
| --- | --- | --- |
| `--space-xxxsmall` | 2 | `ref/space/100` |
| `--space-xxsmall` | 4 | `ref/space/200` |
| `--space-xsmall` | 8 | `ref/space/300` |
| `--space-small` | 12 | `ref/space/400` |
| `--space-medium` | 16 | `ref/space/500` |
| `--space-large` | 20 | `ref/space/600` |
| `--space-xlarge` | 24 | `ref/space/700` |
| `--space-xxlarge` | 28 | `ref/space/800` |

The ramp runs on 4px steps from 4 up; 2 and 1 (`ref/space/50`) exist below it. Compact and Comfortable shift each step by 4 (e.g. `ref/space/500` = 16 / 12 / 20).

The review rounds a hard-coded px to the nearest of these and names it (`scripts/review/rules.mjs:23-26`).

### 2.2 Radius and border **[code]**

`--radius-small` 2, `--radius-medium` 4, `--radius-large` 8, `--radius-full` 9999. Kit roles on top: `--radius-control-small|medium|large`, `--radius-surface` 8, `--radius-pill` 9999.

`--border-width-thin` 1, `-medium` 2, `-thick` 3. Roles: `--border-control` 1, `--border-control-strong` 2, `--border-surface` 1, `--border-divider` 1, `--border-divider-strong` 2, `--border-focus` 2.

Radius and border width have **no density modes** — one value everywhere (`scale.txt` comment, confirmed: those rows have one column).

### 2.3 Icon and control sizes **[code]**

- Icons: xsmall 12, small 16, medium 20, large 24, xlarge 32. `icon/size/xsmall` is marked "not in Figma" — kit-only, for Badge glyphs, fixed in every density.
- Controls: `--control-small` 28, `--control-medium` 36, `--control-large` 44. These are the `sm` / `md` / `lg` heights of every control (Button, Input, Select, …).
- `--target-min` 24 — the minimum hit area (WCAG 2.5.8); `Input.module.css:22` grows a 16px help icon to it with a pseudo-element.

### 2.4 Type **[code]**

Font size roles: `--font-size-xsmall` 12, `-small` 14, `-regular` 16, `-large` 18, `-xlarge` 20, `-xxlarge` 24. Weights 400 / 500 / 600 / 700 as `regular` / `medium` / `semibold` / `bold`. Line heights `tight` 1.2, `snug` 1.35, `normal` 1.5, `relaxed` 1.65, `loose` 2. Letter spacing `tight` -0.02em, `normal` 0, `wide` 0.04em.

Text **roles** live in `src/tokens/typography.css` as four vars each: `--text-<role>-size`, `-weight`, `-lh`, `-ls`. A component sets all four together (`Button.module.css:32-34`). Role families: `display`, `metric`, `heading-xs…xl`, `title-xxs…xl`, `body`, `body-lg`, `body-snug`, `body-tight`, plus BP reference aliases `--text-ref-label-button-*`, `--text-ref-label-form-*`, `--text-ref-cell-*`. The roles match the 42 Figma text styles (commit `5c9eb13`).

Never write a raw `font-size: 14px` in a component. **[code]** — `bp/raw-value` does not flag font-size today, so this one is enforced by convention and review of colour/space/radius/shadow only. **[guess]** that a font-size literal would be rejected in review by a human.

### 2.5 Layout **[code]** (`src/tokens/layout.css`, `contracts/layout.json`)

Classes, not per-page grids: `.layout-app`, `.layout-header`, `.layout-canvas`, `.layout-workspace`, `.layout-content`, `.layout-stack`, `.layout-metrics`, `.layout-split`, `.layout-container-sm…2xl`.

- `.layout-content` owns the page inset (`--layout-margin-md`, 24px) and the gap between stacked children (`--layout-gutter-lg`, 24px). `Section` does not own page padding.
- A column of Sections inside another layout uses `.layout-stack` (same gap, no padding).
- `--layout-column-max` 554px caps a form/record column.
- Media queries use literal px because CSS vars cannot appear in a media query (`layout.css:2-3`). This is the one sanctioned raw value.

## 3. Naming and file layout

### 3.1 Files **[code]**

```
src/ui/<Name>/<Name>.tsx          # the component, named export `<Name>`
src/ui/<Name>/<Name>.module.css   # its styles
contracts/<name>.json             # lower-case, no separators: BadgeAlt → badgealt.json
```

Patterns: `src/patterns/<Name>/<Name>.tsx`. The contract's `path` field points at the `.tsx` (`contracts/button.json:3`). Import path in a screen: `@/ui/<Name>/<Name>`.

The `.tsx` holds for all 85 components. The `<Name>.module.css` beside it does **not** — seven pieces differ, and a new piece should follow the pattern unless it has the same reason: **[code]**

- `src/ui/Chart/` is a shared folder, not a component: `chart.tsx`, `XYChart.tsx` and `chart.module.css`, used by the chart components. It has no contract of its own.
- `BarChart` and `LineChart` carry **no CSS file at all**; they style through the shared chart module.
- `FunnelChart`, `RadarChart`, `ScatterChart` and `WaterfallChart` each keep a **lower-case** module (`funnel.module.css`, `radar.module.css`, `scatter.module.css`, `waterfall.module.css`).
- `Select` has no module of its own: it imports the field styles, `import field from "../Input/Input.module.css"` (`src/ui/Select/Select.tsx:11`). Textarea-shaped fields share the label, hint and error rules this way.

**[guess]** the lower-case-no-separator contract filename is a hard rule — it holds for all 96 contracts, but no test I found asserts it; `index.json` carries the path explicitly.

### 3.2 Props **[code]**

- `intent` is the colour-role prop, never `tone`: `brand | neutral | danger | success | warning | info` and the extended hues, per contract. One `tone` exists — `Skeleton` `default | band | brand` — and it names the surface the skeleton sits on, not a colour role. **[code]**
- `emphasis` is loudness: `strong | subtle | minimal`. It is the right prop for how loud a control is, and a new piece should not add a `variant` for that. `variant` does exist where a piece has two genuinely different shapes: `AnchorNav` `rail | menu`, `Cascader` `field | panel`, `Form` `plain | card`, `GlobalSearch` `list | tabs`. **[code]**
- `size` is `sm | md | lg` (a few pieces add `xs`, `xl`, `full`, `fullscreen`; the catalog sorts them in that order, `Master.tsx:34`).
- Booleans are off by default and read as adjectives: `disabled`, `loading`, `iconOnly`, `fullWidth`, `required`, `invalid`, `readOnly`, `hideLabel`, `toggle`.
- `children` carries the label text.
- Icons are Material Symbols **names** as strings (`iconStart="add"`), rendered through the kit `Icon`.
- Handlers, `data-*`, `aria-*`, and a short free list (`key`, `ref`, `className`, `style`, `id`, `children`, `title`, `role`, `tabIndex`, `hidden`, `form`, `name`, `value`, `autoFocus`) need no contract entry (`scripts/review/catalog.mjs:22-33`).

### 3.3 Levels **[code]** (`scripts/sync-index.mjs:12`, `tests/contract-levels.test.ts`)

`atom | molecule | organism | template`. Patterns are always `template`; components never are. Foundations (only `Layout` today) carry no level. The contract is the source of truth; `npm run sync:index` copies the level into `contracts/index.json`, and the test fails on drift.

Today: 23 atoms, 33 molecules, 29 organisms, 10 templates.

### 3.4 Index rows **[code]**

`contracts/index.json` → `{ version, components[], patterns[], foundations[] }`.

- component row: `name`, `contract`, `level`, `category`, `tags[]`
- pattern row: `name`, `contract`, `level`, `tags[]`
- foundation row: `name`, `contract`, `tags[]`

Categories in use: `data`, `navigation`, `form`, `feedback`, `overlay`, `base`, `layout`, `brand`. **[guess]** that this list is closed — nothing enforces it.

## 4. The contract

### 4.1 Fields **[code]** (`src/playground/Master.tsx:26-33`)

Required of every contract, all 96 of them: `name`, `path`, `intent`, `useWhen[]`, `doNot[]`, `a11y[]`, `snippet`.

Required of every **component and pattern** contract, and optional in the `Contract` type (`Master.tsx:26-33` marks `level`, `figma`, `usage` and `examples` optional): `level`, `figma { fileKey, nodeId }`, `usage`, `props`, `examples[]`.

- `layout.json` is the exception on every count: no `props`, no `examples`, no `level`, no `figma`. It is the one foundation contract, and foundations carry no level (`tests/contract-levels.test.ts`).
- `figma` is absent on `layout.json` and `density.json` (nothing to draw). Every **component** contract names its Figma component (commit `fea69d8`, `tests/figma-links.test.ts`), so a new component needs it.
- `composes[]` appears on 24 contracts: the kit pieces a bigger piece is made of. The review uses it to say "reuse this bigger piece" when a screen hand-rolls ≥60% of a piece's parts, minimum 3 (`scripts/review/rules.mjs:13-16`).
- `doNot` must contain at least one "when not to use" line, or `tests/contract-docs.test.tsx` fails. Two mechanical stops are special-cased into a side panel: a "Do not invent a local …" line and a "Do not use raw hex" line.

### 4.2 Prop entry shape **[code]**

```json
"emphasis": { "enum": ["strong","subtle","minimal"], "default": "subtle", "note": "…" }
"label":    { "type": "string", "required": true, "note": "…" }
"items":    { "type": "array", "itemShape": { "id": "string", "label": "string" } }
```

`noteForFigma: true` marks a note written for the Figma mirror. Enums are **closed**: a screen passing a value outside one is a review error `bp/closed-enum`.

### 4.3 Examples **[code]**

`examples[]` → `{ title, usage?, a11y?, code?, items: [{ caption?, props }] }`. The playground Variants tab renders them straight from the contract, and `tests/contracts.test.tsx` renders **every item of every example** through the registry, failing on any React error or axe violation. So a contract example is a test: it must be renderable with real props.

Conventions:

- Size examples go sm → md → lg. **[code]**
- An `a11y: true` example comes first. This skill asks for it on new work, but it is **not** how the kit looks today: only `Button`, `Callout` and `Icon` open with an "Accessibility" example, and eight more contracts carry an `a11y: true` example somewhere further down under its own name (`appheader` "Built in", `form` "Form error", `tabs` "With panels", …). Eighty-five contracts have no `a11y` example at all. Not tagged [code].

## 5. Variants and states, in code

### 5.1 Enum → class **[code]** (`src/ui/Button/Button.tsx:82-96`)

Each enum value becomes a CSS module class of the same name, joined into one `className`:

```tsx
const cls = [styles.button, styles[emphasis], styles[intent], styles[size],
             iconOnly ? styles.iconOnly : "", …].join(" ").trim();
```

Allowed combinations are typed, not just documented: `ButtonLook` is a discriminated union, so `emphasis="strong" intent="neutral"` fails typecheck (`Button.tsx:28-33`).

### 5.2 The state recipe **[code]**

| State | How | Tokens |
| --- | --- | --- |
| hover | `:hover:not(:disabled, .loading)` | `--bg-*-hover`, `--bg-*-faint` |
| press | `:active:not(:disabled, .loading)` | `--bg-*-press`, `--bg-*-faint-press` |
| focus | `:focus-visible { outline: var(--border-width-medium) solid var(--outline-brand); outline-offset: var(--focus-offset); }`; danger swaps `--outline-danger` | `--outline-brand`, `--outline-danger` |
| disabled | native `disabled` + `cursor: not-allowed; opacity: var(--opacity-disabled)` | `--opacity-disabled` |
| selected | `--bg-neutral-min-selected`, `…-selected-hover`, `…-selected-press` | semantic `/selected` family |
| error | red border + message under the field; `invalid` is the border alone | `--border-danger`, `--text-danger` |
| loading | `aria-busy` + `aria-disabled`, full colour kept, click swallowed, spinner over hidden content | `--motion-*` |
| toggle on | brand tint + brand border + `aria-pressed` (dropped when `aria-expanded` is present) | `--bg-brand-faint`, `--border-brand-subtle` |

Transitions: `transition-property: background-color, border-color, color;` with `--motion-interaction-duration` and `--motion-interaction-easing` (`Button.module.css:13-15`).

Semantic state suffixes exist as tokens, so a component never computes a hover colour: `/hover`, `/press`, `/selected`, `/selected/hover`, `/selected/press`, `/static`, `/contrast`.

### 5.3 Loading has two meanings **[code]**

- `loading` prop — this one control is working (spinner, keeps colour).
- Page boot — the page says loading once through `FormLayoutContext` (set by RecordPage, ListPage, FormPage, Dashboard) and each piece draws its own `Skeleton` in its own place (`Button.tsx:78-85`, `useFieldSkeleton`). A control standing on a booting page takes **no** loading prop of its own. Pieces that draw their children's blocks (Toolbar, Section, Card, Timeline) never reach the leaf.

### 5.4 Density and groups **[code]**

A control reads its size in this order: the group's size (`ButtonGroupContext`), then its own `size` prop, then the surrounding `Density` (`useDensitySize`). Density changes the token values, not the enum (commit `b81bdfe`).

### 5.5 Inspect tags **[code]**

Every kit piece spreads `inspect("<Name>")` onto its root element, so `npm run review -- --url` can name the pieces in server-rendered HTML (`src/ui/inspect.ts`, `Button.tsx:102`).

## 6. Light and dark

**[code]**

- Dark is a token-layer concern: `ui.txt` and `semantic.txt` carry a Light and a Dark column, and `[data-theme="dark"]` redeclares the roles. A component writes one set of colours.
- Things that must not flip use the paired `/static` and `/contrast` roles — e.g. `--text-neutral-min-static` for the label on a filled brand button (commit `2e4fbfc`, "Turn component dark overrides into paired contrast tokens").
- `data-theme` appears in two kinds of place, and nowhere else:
  - Four CSS modules, all brand marks: `Badge`, `Count`, `Logo`, `LogoAI` — they read the theme to keep the mark legible.
  - `GuidedProcess.tsx`, which **forces** `data-theme="dark"` on two elements: the process panel (`:118`) and the table-of-contents inner wrapper (`:171`). It is a dark island on a light page, so it sets the theme instead of writing dark colours.
- So a new component either reads the theme (a mark) or forces it for a deliberate dark island. Any other `data-theme` block is a smell: use the `/static` and `/contrast` roles.

## 7. Limits a builder must respect

**[code]**, each from the named contract:

- One `emphasis="strong" intent="brand"` Button per view (review rule `bp/one-primary`).
- Avatar initials: two letters max.
- Count: default `max` 99; above it reads `99+`.
- AvatarGroup: faces past `max` collapse into `+N`.
- Dashboard row: up to 5 tiles (`layout-metrics--fixed-5`).
- Form / record split: up to 4 blocks (`layout-split--thirds`, `--quarters`).
- Form fields: `columns` up to 3, each column capped at `--layout-column-max` 554px (FormPage says 480px for its own case — see §9).
- Card `description`: two lines at most.
- Callout: one or two sentences, at most one action. In a prototype every Callout gets `closeButton`, and sits **above** the section it relates to.
- NavTile `description`: one line, no paragraph.
- Cell: badges for up to three labels.
- ListView boot skeleton: at most 12 rows.
- AppHeader logo: up to 116px wide, else the name.
- Breadcrumbs read `Home › side-nav section › current screen`; PageHeader appends the page title itself.
- Full screens sit in `AppShell` with the whole nav: `items={APP_NAV}`, `endItems={APP_NAV_END}`.

**[guess]** there is no general max text length. Length caps exist only where a contract names one; everything else is prose guidance.

## 8. The gates a new piece must pass

**[code]**

1. `npm run tokens` — only if a token changed; regenerates the two CSS files.
2. `npm run sync:index` — copies levels into the index (`--check` in CI-style use).
3. `npm test` — `contracts.test.tsx` (every example renders + axe), `contract-levels.test.ts`, `contract-docs.test.tsx`, `figma-links.test.ts`, plus the piece's own test.
4. `npm run review -- <file>` — rules `bp/raw-value`, `bp/primitive-token`, `bp/local-cousin`, `bp/closed-enum`, `bp/one-primary`, `bp/use-pattern`, `bp/use-bigger-piece`, `bp/screen-frame`. The review skips the kit's own folders (`src/ui`, `src/patterns`, `src/tokens`, playground, tests) — it is for screens, not for the kit.
5. `npm run build` / `npm run lint`.

The playground needs **no new route**: `/components/[slug]` and `/patterns/[slug]` are generated from `contracts/index.json`, and the piece is rendered by its `registry` entry (`src/playground/registry.tsx`, keyed by contract `name`, with `render`, `preview`, optional `hide[]` and `normalize()`).

Known cousins the review rejects by name: `EmptyHeader`, `Dialog`, `Sheet`, `SliderThumb`, `ToastAction` (`scripts/review/catalog.mjs:12`). The review never suggests the chat pieces (`ChatWindow`, `ChatComposer`, `ChatHeader`, `ChatList`, `ChatMessage`).

## 9. Where the sources disagree

1. **`CLAUDE.md` vs the catalog.** CLAUDE.md says "the catalog will grow past 30 components"; there are already 85 components and 10 patterns. **[code]**
2. **Index level vs contract level.** Two copies of the same fact, kept in step by `npm run sync:index` and a test. The contract wins. **[code]**
3. **Figma vs code.** `scale.txt` marks several roles "not in Figma": `icon/size/xsmall` 12, the line-height and letter-spacing ramps, the kit radius/border roles, `ref/space/1700` 64. `AGENTS.md` adds two tokens that exist **only** in the Paper doc file (`--text-page-title-size`, `--letter-spacing-wider`) and are not kit code tokens. **[code]**
4. **Column cap.** 554px (`--layout-column-max`) is the live number: it is a token and `form.json` names it. 480px is still written in three contracts — `formpage.json` (`props.columns.note`), `form.json` (a `doNot` line) and `recordpage.json` (`props.columns.note` and one example's `usage`). Those four lines are stale prose, not a second rule. **[code]** that they differ; **[guess]** that 480 is simply out of date. Fixing them is a contract change, out of scope here.
5. **The "not built yet" list.** `.claude/skills/prototype-from-kit/SKILL.md` lists pieces to stop and ask about; `Table` and `Scoreboard` were already shipped and had to be corrected inline. The list drifts; `contracts/index.json` is the truth. **[code]**
6. **Font-size literals.** Rules say "no raw values", but `bp/raw-value` only checks colour, spacing, radius and shadow. Type literals pass review. **[code]**
